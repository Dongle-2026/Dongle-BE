# 노션 API 검증 후 1차 수정

## 수정 범위와 이유

기준 자료는 `api-audit/NOTION_SOURCE_2026-10-08.md`이며, 최초 재현 결과는
`NOTION_API_AUDIT_2026-10-11.md`에 보존한다. 이 문서는 그 이후 수정 내역이다.
29개 API 전체 완료를 의미하지 않는다. 상세 요청/응답 페이지는 제공된 ZIP에 없다.

| 항목 | 확인한 문제 | 수정 |
|---|---|---|
| A4 뉴스 목록 | 검색어가 null인 실행에서 PostgreSQL lower(bytea), HTTP 500 | JPA Specification으로 실제 입력된 조건만 조합. nullable LIKE 바인딩 제거 |
| A14 읽음 | 재요청마다 행 추가, 학습 통계 부풀림 | 사용자 행 잠금 후 한국 날짜 기준 존재 여부 확인 및 삽입 |
| A2 토큰 갱신 | 노션 경로 404 | POST /api/auth/refresh 추가. 기존 /reissue 유지 |
| A6/A7 저장/해제 | 노션 경로 404 | POST /api/news/{id}/save, /unsave 추가. 기존 멱등 서비스 재사용 |
| A15 검색 | search가 기사 ID로 해석되어 400 | GET /api/news/search?q=검색어 추가 |

## 확정된 읽음 정책

사용자 결정: **한국 시간(Asia/Seoul), 같은 사용자·같은 기사·하루 1회**.
다음 날 다시 읽으면 새로운 기록을 남긴다. 같은 날 재요청은 기존 기록을 유지하며
durationSeconds를 누적하거나 덮어쓰지 않는다.

- DB statement_timestamp()로 삽입 시각과 당일 경계를 계산하므로 JVM/DB 기본 시간대에 의존하지 않는다.
- 서비스 트랜잭션에서 사용자 행을 잠가 같은 사용자의 동시 쓰기를 직렬화한다.
- 기존 중복 이력은 삭제하지 않는다. readNewsCount는 기사·한국 날짜의 고유 조합을 센다.
- 연속 학습일도 한국 날짜로 계산한다.
- 새 스키마나 원본 DB 마이그레이션은 필요 없다.
- 이 보장은 해당 서비스 경유 쓰기에 적용된다. DB 직접 INSERT까지 막는 유니크 제약은 추가하지 않았다.

## API 호환성

새 경로는 기존 서비스와 응답 DTO를 재사용한다. refresh 요청은
`{"refreshToken":"..."}`, 저장/해제 응답 data는 `{"bookmarked":true/false}`다.
보호된 저장/해제는 Bearer accessToken이 필요하다. 검색은 기존 뉴스 공개 정책을 유지한다.

**노션 전체 계약 일치로 판정하지 않는다.** 현재 목록은 data.content 형태의 Spring Page,
page=0부터 시작, size 파라미터를 사용한다. 노션 page=1/limit/meta, 문자열 ID,
오류 error 필드, 날짜 offset은 아직 불일치한다. 이를 전역 변경하면 현재 앱의
서비스 매핑이 깨지므로 별도 계약 정리 및 앱 동시 변경이 필요하다.

## 검증 방법

최종 실행: 총 112건, 성공 111건, 실패 0건, 실제 AI 전용 테스트 1건 조건부 제외.
노션 경로 등록은 4개에서 8개로 늘었으며, 신규 경로 포함 8개 정상 요청은 HTTP 200.
나머지 21개 경로와 전체 응답 계약은 아직 완료되지 않았다.

```sh
RUN_NOTION_API_AUDIT=true ./gradlew test --no-daemon
```

- PostgreSQL 테스트 DB 5433, Redis 테스트 6380 사용. 원본 DB 15432는 변경하지 않음.
- 검색 필터 없음/검색어/카테고리/날짜를 반복·교차 호출하는 회귀 테스트 추가.
- 어제 한국 시각 23:59:59의 중복 기록을 보존하면서 오늘 두 번 요청해 한 건만 추가되는지 검증.
- 저장/해제 반복 호출, 인증 없는 요청 거부, 검색 결과, refresh 회전 검증.
- 노션 감사 테스트의 경로 등록 기대값을 신규 경로에 맞게 갱신.
- MockMvc 통합 검증이며 실제 iPhone, OAuth 제공자, AI 추론 검증은 별개.
- 감사 테스트에서 미구현 경로의 404를 확인한 테스트가 통과해도 해당 기능이 완성됐다는 뜻은 아니다.

## 남은 작업

1. A8/A9/A17 등 기존 사용자 서비스의 노션 경로·DTO 호환 계층.
2. A12/A13/A16 독립적인 용어 저장 기능과 데이터 모델(학습 이력과 분리).
3. 읽기 이력/활동, 카테고리/키워드, 알림 설정 구현.
4. A1 모바일 OAuth: 제공자별 code/idToken 입력 및 앱 callback 규약 확정 필요.
5. A11 퀴즈: 문제/정답 데이터 및 재응시·포인트 규칙 확정 필요. 가짜 성공 응답을 만들지 않음.
6. multipart 프로필 이미지: 파일 저장 위치·크기·허용 형식 결정 및 구현.
7. 인사이트/인기검색/추천검색: 계산 근거·집계 기간과 개인정보 처리 규칙 확정 후 구현.

정확한 노션 계약 대조를 마치려면 **API 각 항목 내부의 요청/응답 예시 페이지**도 필요하다.
