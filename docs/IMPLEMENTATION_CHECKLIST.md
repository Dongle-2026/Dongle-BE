## 기존 API 재사용 범위

- 인증 `/api/auth/*`, 프로필 `/api/users/me/*`
- 뉴스 `/api/news`, `/today`, `/{id}`, `/{id}/read`, `/{id}/bookmark`
- 카드 `/api/card-news`, `/article/{articleId}`, `/{cardNewsId}`, `/{articleId}/generate`
- 용어 `/api/terms/*`, 정책 `/api/policies/*`
- 소비 `/api/spending/*`, 알림 `/api/notifications/*`

URL은 기존 컨트롤러 기준이다. 제안서의 예시 URL을 그대로 추가해 중복 API를 만들지 않는다. 실제 Swagger가 최종 계약이다.

## 기술 결정

1. 앱→Spring→Node→Ollama: 앱에는 모델 주소·키·프롬프트를 노출하지 않고 Spring에서 소유권/집계를 처리한다.
2. Node 서비스를 이 저장소 `ai-service/`에 추가: 별도 저장소가 없어도 재현 가능한 계약과 로컬 실행 환경을 제공한다. 팀의 기존 AI 서비스가 있으면 동일 HTTP 계약으로 교체 가능하다.
3. 실제 생성은 실패를 반환하고 기존 카드는 보존: 검증되지 않은 생성문이나 스텁을 실제 게시물로 가장하지 않는다.
4. 소비는 BigDecimal 집계 후 LLM에 집계값만 전달: 메모/이메일 전송과 계산 오류를 줄인다.
5. 현재 Flyway 의존성은 없다. SQL 파일 존재만으로 자동 적용된다고 안내하지 않는다. 기존 DB 삭제·재생성은 하지 않는다.
