# AI 장애 관측 — 2026-09-29

## 문제와 이번 변경

기존 Spring 로그에는 HTTP 503과 예외 클래스만 남아 모델 시간 초과, 연결 실패, 출력 검증 실패를 구분하기 어려웠다. 자동 재시도를 넣기 전에 원인별로 실패를 구분할 수 있어야 한다.

- Spring은 호출마다 UUID를 만들고 Node에 `X-Request-ID`로 전달한다.
- Spring 로그: 요청 ID, 내부 경로, HTTP 상태, 허용 목록의 오류 코드, 처리 시간. 응답 본문과 예외 메시지는 출력하지 않는다.
- Node 요청 로그: 요청 ID, 등록된 라우트, 상태, 오류 코드, 처리 시간. 임의 URL이나 쿼리 문자열은 기록하지 않는다.
- Ollama 단계 로그: `/api/chat`, `/api/embed` 등 단계, 상태, 오류 코드, 처리 시간. 모델 출력이나 기사 원문은 기록하지 않는다. 단계 로그 자체에는 요청 ID가 없으므로 요청 단위 로그와 구분한다.
- `OLLAMA_TIMEOUT` 또는 Spring의 응답 제한 시간 초과는 기존 `AI_SERVICE_TIMEOUT`(HTTP 504)으로 매핑한다. 그 외 AI 장애는 기존 503 응답을 유지한다.

## 해석 방법

| 관측 값 | 의미 | 다음 확인 |
|---|---|---|
| OLLAMA_TIMEOUT, status=0 | 응답 수신 전 설정한 제한 시간 초과 | 모델 로딩·장비 부하·입력 길이 측정 |
| OLLAMA_UNAVAILABLE | 네트워크/응답 읽기 등 호출 실패 | Ollama 실행·주소·네트워크 확인 |
| OLLAMA_ERROR, status=4xx/5xx | Ollama가 실패 상태 반환 | 모델 설치 및 Ollama 서버 로그 확인 |
| INVALID_MODEL_JSON / INVALID_CARDS 등 | 결과 형식/근거 검증 실패 | 평가 입력으로 재현, 프롬프트/검증 계약 검토 |
| AI_BUSY | Node의 동시 작업 제한 | 즉시 반복 요청하지 않고 작업 큐에서 대기 |
| AI_UNKNOWN_ERROR | 허용 목록 외 응답 | 서비스 버전·계약 확인. 원문 응답을 일반 로그로 출력하지 않음 |

실행: `cd ai-service && node scripts/diagnose.mjs`. 고정된 짧은 가상 기사로 요약과 임베딩 단계의 시간을 출력한다. 민감한 실제 기사를 인자로 받지 않는다. 일반 서비스에 적용하려면 Node와 Spring을 변경된 코드로 재시작해야 한다.

## 검증 및 한계

타임아웃 분류, 알 수 없는 응답 마스킹, 요청 ID 전달, 단계별 로그의 원문 미포함, 로거 장애 격리를 자동 테스트한다. 이 테스트는 실제 모델의 지연 문제가 해결되었다는 증거가 아니다.

후속 개발로 [비동기 AI 작업 API](AI_JOBS.md)를 추가했다. 기존 동기 API도 호환을 위해 유지한다. 모델 지연 자체와 실제 앱 전체 경로는 별도 검증이 필요하다.
