# 카드뉴스 정확성·웹 조회 보완 (2026-10-16)

로그인 구현은 이번 변경 범위에서 제외했다. 기존 인증이 필요한 저장·읽음·개인 정보 API의 보호는 유지한다.

## 구현

자동 파이프라인 기본값은 `CARD_GENERATION_MODE=extractive`다. AI는 후보 문장 중 5개 번호만 선택하고 카드 본문은 원문을 그대로 사용한다. 첫 문장을 반드시 포함하고 원문 순서를 유지하며 200자를 넘는 문장은 잘라 쓰지 않는다. 후보가 부족하거나 번호가 잘못되면 실패 처리한다. 버전은 `card-v5-source-excerpts`이며 UI에 원문 발췌임을 표시한다. 원문에 잘못된 정보가 있거나 문맥이 생략되는 한계는 남는다.

아래 자유 요약 방식은 `rewrite` 모드에서 사용한다. 실제 기사 시험에서 첫 결과가 의미 검수에서 거부되고 재생성이 시간 초과되어 파이프라인 기본값으로 채택하지 않았다.

- 카드 생성 프롬프트: 짧게 압축하다 조건을 누락하지 않도록 본문 최대 160자를 권장하고, 원문에 없는 배경·용어 정의·영향을 강제로 채우지 않는다.
- 카드 생성 뒤 별도 모델 호출로 제목·본문의 모든 주장을 근거와 대조한다. 대상·단위·시점·조건·최대/최소·부정·예정/확정을 검사한다. 하나라도 불확실하거나 검수 응답이 누락/중복/잘못된 형식이면 거부한다. 전체 기사의 개편안·전망 맥락도 제공한다.
- 검증 실패 시 1회 재생성. 다시 실패하면 결과를 반환하지 않아 기존 저장 카드를 교체하지 않는다. 프롬프트 버전 `card-v4-evidence-review`.
- 카드·퀴즈의 여러 모델 호출에 총 510초 예산을 적용한다. Spring 기본 540초, 작업 임대 600초 이내에 종료하도록 한다. 개별 모델 호출은 기존 240초 상한을 유지한다.
- Spring 숫자 검증에 highlight도 포함한다.
- `GET /api/news/{articleId}/generation`: 로그인 없이 기사 요약/카드/퀴즈의 최신 작업 상태만 조회한다. 내부 오류·작업 식별자는 노출하지 않는다. 기존 결과가 있는 상태에서 재생성 중일 수도 있으므로 결과 존재 여부와 작업 상태는 별개다.
- 웹 미리보기: 현재 접속 주소의 API 사용, 루트에서 홈 이동, 샘플 뉴스로 오류를 숨기지 않음, 서버 검색·20건 페이지 이동, 기사에서 카드·퀴즈·생성 상태 확인.
- 카드 뷰어: 각 카드에 저장된 문장 ID로 원문 근거 표시. 이전 프롬프트 결과와 stub을 구분해 표시. 숫자 기사 ID 검사, 화면 이동 요청 경합 방지, 키보드로 목차 버튼 사용.

## 실행

저장소에서 `./run-pipeline`을 실행하고 http://localhost:18082/ 에 접속한다.
기존 카드가 자동으로 새 버전이 되는 것은 아니다. 재생성은 기존 관리자 작업 API 또는 실패 작업 재시도 흐름으로 별도 실행한다.

## 한계와 남은 항목

같은 로컬 모델의 추가 검수는 사람의 원문 대조를 대체하지 않는다. 의미 검수로 생성 시간이 증가하고 거부 비율도 높아질 수 있다. 기사 20건 품질 평가는 별도 증거가 필요하며 자동 테스트 통과를 정확도 수치로 해석하지 않는다.
