## 0. 프론트가 먼저 알아야 할 공통 규칙

| 항목 | 규칙 |
|---|---|
| 주소 | `http://<맥북 IP 또는 서버>:8080` + 경로. 휴대폰에서 `localhost`는 휴대폰 자신이다. AI 서버(3000)는 앱이 직접 부르지 않는다 |
| 인증 | `Authorization: Bearer <accessToken>`. 표의 '인증' 열 참고. '선택'은 토큰이 있으면 개인화 정보가 추가됨 |
| 토큰 | access 15분, refresh 7일. 401이면 `POST /api/auth/refresh`로 1회 갱신 후 재시도, 새 refreshToken으로 교체 저장 |
| 성공 응답 | `{"status":200,"message":"ok","data":...}`. message는 바뀔 수 있으니 분기에 쓰지 않는다 |
| null | **값이 null인 필드는 JSON에서 아예 빠진다.** "필드 없음 = null"로 처리 |
| 목록 | 대부분 Spring Page: `data.content`(목록), `data.last`(마지막 페이지면 true), `data.number`, `data.size`, `data.totalElements` |
| 페이지 | `page`는 **0부터**, 크기는 `size`(`limit` 아님). 앱의 page=1 → 서버 page=0 |
| ID | 서버는 숫자. 앱에서 `String(id)`로 바꿔 쓰고, 요청 시 그 숫자 그대로 보낸다(`news-` 같은 접두사 금지) |
| 날짜 | `2026-10-11T15:03:04.227` 형식(오프셋 없음). 날짜만은 `YYYY-MM-DD`. 활동/학습 날짜 경계는 한국 시간 |
| 오류 | HTTP 상태코드로 먼저 분기. 본문은 `{"status":4006,"message":"..."}` — body.status는 HTTP 코드가 아니라 아래 표의 내부 코드 |
| 반복 요청 | 저장/해제/읽음/설정 변경/퀴즈 보상은 같은 요청을 여러 번 보내도 결과가 1번만 반영된다 |

## 1. 앱 최신 타입(Dongle-APP main 07c31fc, 10/11)과 서버 응답 변환

앱 연결은 **앱 저장소 main 기준**이다. main은 아직 목업이므로 services에서 아래처럼 변환한다.

| 앱 타입 | 서버 API | 변환 |
|---|---|---|
| `News` (목록) | `GET /api/news`, `/api/news/search`, `/api/news/today` | id←`String(id)`, description←`summary`, createdAt←`publishedAt`, image←`image`(없으면 기본 이미지), isSaved←`isSaved`(로그인 시) |
| `News` (상세) | `GET /api/news/{id}` | content←`content`, url←`sourceUrl` |
| `NewsBodyData` | `GET /api/news/{id}/body` | newsId←`String(newsId)`, sections[].subtitle 없음(빈 값 처리), `quizResults`←각 `quizzes[].myResult`를 `{quizId, ...}`로 모음, intro 없으면 빈 문자열 |
| `Term` | body의 `terms[]` | id←`String(termId)`, isSaved←`saved`, definition←`definition` |
| `Quiz` | body의 `quizzes[]` | **answerIndex·explanation은 서버가 주지 않는다**(제출 응답에서만). 타입에서 optional로 바꾸고 클라이언트 채점 제거 |
| `SubmitQuizResponse` | `POST /api/quizzes/{id}/answer` | alreadyAnswered←`alreadySolved`(이미 맞힌 문제), totalHoney←`totalHoney`, revealed. 오답이면 correctIndex·explanation 없음 → **오답 후 '정답 보기' 버튼**: `POST /api/quizzes/{id}/reveal`(누르면 그 문제 꿀 없음) |
| `TermAction` | `POST /api/terms/{id}/save` | 서버 data는 `{bookmarked}`. termId·action·timestamp는 앱이 요청 정보로 만든다 |
| `UserAction` | `POST /api/news/{id}/save` | 위와 같음(`{bookmarked}`) |
| `UserProfile` | `GET /api/me` | id←`String(id)`, oauthProvider←`oauthProvider`(kakao/google, 이메일 가입은 없음). **앱 타입의 'naver'를 'google'로 바꿔야 함**(카카오·구글로 확정) |
| `UserStats` | `GET /api/me/stats` | streak←`consecutiveLearningDays`, quizCount←`totalQuizCount`, todayHoney·correctCount·totalHoney·readNewsCount 그대로 |
| `UserActivity` | `GET /api/me/insights` | interests←`interestedCategories`, weaks←`weakCategories` (correctRate·totalQuizCount도 제공) |
| `ActivityDay[]` | `GET /api/me/activity` | 그대로 |
| `NotificationSetting` | `GET/PATCH /api/me/notification-settings` | 그대로. 끈 항목은 푸시 안 보냄 |
| 푸시 토큰 | `POST /api/me/devices` | expo-notifications `getExpoPushTokenAsync()` 결과(ExponentPushToken[...]). 로그아웃 때 `DELETE /api/users/me/devices/{deviceId}` |
| `ProfileEditInput` | `PATCH /api/me/profile` | FormData: nickname, bio, avatarId, image(파일), image===null이면 removeImage=true. Content-Type 헤더 직접 지정 금지 |
| `Category` | `GET /api/categories` | 그대로. '전체'는 앱에서 앞에 추가 |
| 검색 키워드 카드 | `GET /api/keywords` | image 있으면 사용, 없으면 기본 이미지 |
| 인기 검색어 | `GET /api/search/trending` | `{rank, keyword, change, isNew}` |
| 최근 검색어 | (서버 없음) | 기기에 저장 |
| `ApiError` | 오류 응답 | error←코드명(위 표) 또는 body.status, status←HTTP 상태코드 |

## 3. API 상세

- 정렬: 영역별, 앱이 쓸 경로 먼저, 그다음 기존 호환/관리자.
- '용도'가 **기존 호환**인 경로는 예전 연결을 위해 남겨둔 것이다. 새 화면은 화살표의 경로를 쓴다.
- 응답 표기: `{필드:타입}`, `[…]`는 배열, `Page{…}`는 위 목록 규칙.

## 인증

### POST `/api/auth/oauth/{provider}` — A1

- **기능**: 모바일 소셜 로그인
- **인증**: 불필요 · **용도**: 앱 사용
- **요청 파라미터**: provider(경로, 필수): string
- **요청 Body**: `{idToken:string, nonce:string}`
- **응답 data**: `{accessToken:string, refreshToken:string, nickname:string, newUser:boolean}`
- **필요 데이터·주의**: provider=kakao|google. 앱 SDK가 받은 OIDC idToken 전송, SDK에 nonce를 넣었다면 같은 값 전송. newUser=true면 온보딩. 401(4006) 토큰 무효, 409(4007) 같은 이메일이 다른 방식으로 가입됨(자동 연결 안 함), 503(5004) 서버 설정 전

### POST `/api/auth/refresh` — A2

- **기능**: 토큰 재발급
- **인증**: 불필요 · **용도**: 앱 사용
- **요청 Body**: `{refreshToken:string}`
- **응답 data**: `{accessToken:string, refreshToken:string, nickname:string}`
- **필요 데이터·주의**: {refreshToken}. 응답의 새 refreshToken으로 교체 저장(이전 것은 무효). 401 받으면 1회 갱신 후 재시도

### POST `/api/auth/logout` — A3

- **기능**: 로그아웃
- **인증**: Bearer 필수 · **용도**: 앱 사용
- **응답 data**: `(data 없음)`
- **필요 데이터·주의**: Bearer 필수. accessToken 차단 + refresh 삭제

### POST `/api/auth/login`

- **기능**: 이메일 로그인
- **인증**: 불필요 · **용도**: 앱 사용
- **요청 Body**: `{email:string, password:string}`
- **응답 data**: `{accessToken:string, refreshToken:string, nickname:string}`
- **필요 데이터·주의**: 소셜 전용 계정은 400(4104)

### POST `/api/auth/signup`

- **기능**: 이메일 회원가입
- **인증**: 불필요 · **용도**: 앱 사용
- **요청 Body**: `{email:string, password:string, name:string, nickname:string}`
- **응답 data**: `{accessToken:string, refreshToken:string, nickname:string}`
- **필요 데이터·주의**: body: email, password(8~100자), name, nickname. 응답 토큰 바로 사용 가능. 이메일 인증 메일은 없음

### POST `/api/auth/reissue`

- **기능**: 토큰 재발급
- **인증**: 불필요 · **용도**: 기존 호환 → 앱은 POST /api/auth/refresh
- **요청 Body**: `{refreshToken:string}`
- **응답 data**: `{accessToken:string, refreshToken:string, nickname:string}`
- **필요 데이터·주의**: Refresh Token → 새 Access/Refresh Token 발급

### DELETE `/api/auth/withdraw`

- **기능**: 회원 탈퇴
- **인증**: Bearer 필수 · **용도**: 기존 호환 → 앱은 DELETE /api/me
- **응답 data**: `(data 없음)`
- **필요 데이터·주의**: soft delete + 토큰 전체 무효화

### GET `/login/oauth2/code/{registrationId}`

- **기능**: OAuth2 콜백 (Spring Security 자동 처리)
- **인증**: 불필요 · **용도**: 웹 전용(앱 사용 안 함)
- **응답 data**: `브라우저 리다이렉트(JSON 아님)`
- **필요 데이터·주의**: 소셜 로그인 완료 후 자동 호출되는 콜백 URL. 직접 호출하지 않습니다.

처리 결과:
- 성공: `http://localhost:3000/auth/callback?accessToken=...&refreshToken=...` 리다이렉트
- 실패: `http://localhost:3000/auth/callback?error=...` 리다이렉트


### GET `/oauth2/authorization/google`

- **기능**: 구글 소셜 로그인
- **인증**: 불필요 · **용도**: 웹 전용(앱 사용 안 함)
- **응답 data**: `브라우저 리다이렉트(JSON 아님)`
- **필요 데이터·주의**: 브라우저에서 직접 접근. 구글 로그인 페이지로 리다이렉트됩니다.

### GET `/oauth2/authorization/kakao`

- **기능**: 카카오 소셜 로그인
- **인증**: 불필요 · **용도**: 웹 전용(앱 사용 안 함)
- **응답 data**: `브라우저 리다이렉트(JSON 아님)`
- **필요 데이터·주의**: 브라우저에서 직접 접근. 카카오 로그인 페이지로 리다이렉트됩니다.


## 뉴스

### GET `/api/news` — A4

- **기능**: 뉴스 목록 조회
- **인증**: 선택(로그인 시 개인화) · **용도**: 앱 사용
- **요청 파라미터**: category(쿼리): string; keyword(쿼리): string; date(쿼리): date(YYYY-MM-DD); page(0부터), size, sort
- **응답 data**: `Page{content: [{id:number, title:string, sourceName:string, category:string, summary:string, publishedAt:datetime, image:string, isSaved:boolean}], last, number, size, totalElements}`
- **필요 데이터·주의**: page는 0부터. 다음 페이지 = data.last=false. category는 youth 같은 id 또는 청년 같은 이름. 로그인 시 각 기사에 isSaved. image=원문 대표 이미지(없으면 생략). 로그인 상태로 keyword 검색 시 트렌드 집계에 기록

### GET `/api/news/{articleId}` — A5

- **기능**: 뉴스 상세 조회
- **인증**: 불필요 · **용도**: 앱 사용
- **요청 파라미터**: articleId(경로, 필수): number
- **응답 data**: `{id:number, title:string, content:string, sourceName:string, sourceUrl:string, category:string, publishedAt:datetime, summary:string, modelVersion:string, termHighlights: [{termId:number, termName:string, simpleDefinition:string, positionStart:number, positionEnd:number}], image:string}`
- **필요 데이터·주의**: 원문·AI 요약·용어 하이라이트(위치 포함)·image

### POST `/api/news/{articleId}/save` — A6

- **기능**: saveNews
- **인증**: Bearer 필수 · **용도**: 앱 사용
- **요청 파라미터**: articleId(경로, 필수): number
- **응답 data**: `{bookmarked:boolean}`
- **필요 데이터·주의**: 반복 호출 안전. data {bookmarked:true}

### POST `/api/news/{articleId}/unsave` — A7
