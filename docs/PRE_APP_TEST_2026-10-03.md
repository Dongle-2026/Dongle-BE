# 앱 테스트 전 개발·검증 기록 (2026-10-03)

## 목표와 완료 기준

아이폰 Expo Go에서 실제 뉴스 조회 → 이메일 가입/로그인 → 뉴스 저장/해제 → 읽음·용어 학습 → 저장 목록과 통계 확인을 수행한다. API 구현, 자동 테스트 통과, 실기기 검증 완료를 구분한다. 이 문서는 실기기 검증 완료 증빙이 아니다.

## 이번 백엔드 변경: 문제 → 선택 → 구현 → 결과

### 인증과 세션

- 문제: 동일한 서명 키를 쓰는 Access/Refresh JWT를 구분하지 않아 Refresh Token이 일반 API 인증에 사용될 수 있었다. 로그아웃·탈퇴 경로도 포괄적인 공개 경로에 포함됐다.
- 선택: JWT 자체의 tokenType 클레임을 확인하고 필터에서 실제 사용자·권한을 조회한다. 모바일 앱 변경만으로는 서버의 인증 취약점을 해결할 수 없기 때문이다.
- 구현: access/refresh 타입 분리, 매 발급마다 UUID jti 부여, 인증 필수 경로 우선 지정, 탈퇴한 사용자 거부, DB의 최신 권한 사용. 사용자 행 잠금으로 Refresh 재발급을 직렬화한다.
- 결과: 같은 순간 재발급해도 토큰이 달라지고 이전 Refresh Token은 거부된다. 이전 버전에서 발급한 타입 없는 토큰도 무효이므로 **업데이트 후 재로그인해야 한다**.
- 제약: Refresh는 사용자별 한 개다. 다른 기기 로그인 시 기존 기기의 다음 갱신이 실패할 수 있다. 멀티 디바이스 세션 관리로 완성됐다는 의미는 아니다.

### 알림 기기 소유권

- 로그아웃·탈퇴 시 사용자 기기 토큰 삭제.
- 같은 기기 토큰이 다른 계정으로 등록되면 기존 소유자 등록을 제거한다. PostgreSQL 트랜잭션 advisory lock으로 등록 경쟁을 직렬화한다.
- 실제 푸시 전송 구현/실기기 권한 설정 완료를 뜻하지 않는다. Expo push token과 FCM token을 혼용하지 말아야 하며 전송 제공자·개발 빌드 설정이 필요하다.

### 뉴스 저장 재시도 안전성

- 기존 POST 토글은 같은 요청을 두 번 보내면 저장이 취소된다.
- 명시적 상태 API 추가: GET /api/news/{id}/bookmark, PUT 동일 경로(저장), DELETE 동일 경로(해제).
- 응답은 기존 GlobalResponse의 data.bookmarked(boolean). 사용자 잠금으로 동시 저장 경쟁을 방지한다. 기존 POST는 호환성을 위해 유지한다.

## 자동 검증

- ./gradlew test --no-daemon: 73개 중 **72 통과, 실제 AI 테스트 1 제외**, 실패 0.
- MobileAuthIntegrationTest: Refresh의 API 사용 거부, 익명 로그아웃/탈퇴 거부, 토큰 고유성·회전, 탈퇴 계정 토큰 거부, 반복 저장/해제 멱등성.
- 소비 분석 기간 테스트를 서버의 UTC 날짜 기준에 맞췄다. 한국시간 자정~오전 9시 사이의 잘못된 실패를 방지한다.
- 테스트 전용 PostgreSQL 5433 / Redis 6380 사용. 원본 DB와 보존용 복제 DB에는 이번 변경으로 삭제·초기화를 수행하지 않았다.

## 완료로 표시하면 안 되는 범위

- 아이폰 실기기 전체 시나리오, 네트워크 단절·재접속 UX.
- 모바일 소셜 로그인 콜백/안전한 코드 교환: 이메일 로그인과 별개다.
- 실제 푸시 발송: 계정·토큰 종류 및 빌드 설정 필요.
- AI 실제 모델 응답 품질 평가와 장시간 큐 부하 검증.
- 공개 배포의 HTTPS·보안 설정·운영 DB 연결 및 백업 복구 검증.
- 퀴즈·포인트 서버 기능: 현재 API 계약이 없어 실제 기능처럼 표시하지 않는다.
