# 앱 테스트 전 개발·검증 기록 (2026-10-03)

## 목표와 완료 기준

아이폰 Expo Go에서 실제 뉴스 조회 → 이메일 가입/로그인 → 뉴스 저장/해제 → 읽음·용어 학습 → 저장 목록과 통계 확인을 수행한다. API 구현, 자동 테스트 통과, 실기기 검증 완료를 구분한다. 이 문서는 실기기 검증 완료 증빙이 아니다.

## 이번 백엔드 변경: 문제 → 선택 → 구현 → 결과

### 인증과 세션

- 문제: 동일한 서명 키를 쓰는 Access/Refresh JWT를 구분하지 않아 Refresh Token이 일반 API 인증에 사용될 수 있었다. 로그아웃·탈퇴 경로도 포괄적인 공개 경로에 포함됐다.
- 선택: JWT 자체의 tokenType 클레임을 확인하고 필터에서 실제 사용자·권한을 조회한다. 모바일 앱 변경만으로는 서버의 인증 취약점을 해결할 수 없기 때문이다.
- 구현: access/refresh 타입 분리, 매 발급마다 UUID jti 부여, 인증 필수 경로 우선 지정, 탈퇴한 사용자 거부, DB의 최신 권한 사용. 사용자 행 잠금으로 Refresh 재발급을 직렬화한다.
- 결과: 같은 순간 재발급해도 토큰이 달라지고 이전 Refresh Token은 거부된다. 이전 버전에서 발급한 타입 없는 토큰도 무효이므로 **업데이트 후 재로그인해야 한다**.
- 제약: Refresh는 사용자별 한 개다. 다른 기기 로그인 시 기존 기기의 다음 갱신이 실패할 수 있다. 멀티 디바이스 세션 관리로 완성됐다는 의미는 아니다.

### 알림 기기 소유권

- 로그아웃·탈퇴 시 사용자 기기 토큰 삭제.
- 같은 기기 토큰이 다른 계정으로 등록되면 기존 소유자 등록을 제거한다. PostgreSQL 트랜잭션 advisory lock으로 등록 경쟁을 직렬화한다.
- 실제 푸시 전송 구현/실기기 권한 설정 완료를 뜻하지 않는다. Expo push token과 FCM token을 혼용하지 말아야 하며 전송 제공자·개발 빌드 설정이 필요하다.

### 뉴스 저장 재시도 안전성

- 기존 POST 토글은 같은 요청을 두 번 보내면 저장이 취소된다.
- 명시적 상태 API 추가: GET /api/news/{id}/bookmark, PUT 동일 경로(저장), DELETE 동일 경로(해제).
- 응답은 기존 GlobalResponse의 data.bookmarked(boolean). 사용자 잠금으로 동시 저장 경쟁을 방지한다. 기존 POST는 호환성을 위해 유지한다.

## 자동 검증

- ./gradlew test --no-daemon: 73개 중 **72 통과, 실제 AI 테스트 1 제외**, 실패 0.
- MobileAuthIntegrationTest: Refresh의 API 사용 거부, 익명 로그아웃/탈퇴 거부, 토큰 고유성·회전, 탈퇴 계정 토큰 거부, 반복 저장/해제 멱등성.
- 소비 분석 기간 테스트를 서버의 UTC 날짜 기준에 맞췄다. 한국시간 자정~오전 9시 사이의 잘못된 실패를 방지한다.
- 테스트 전용 PostgreSQL 5433 / Redis 6380 사용. 원본 DB와 보존용 복제 DB에는 이번 변경으로 삭제·초기화를 수행하지 않았다.

## 완료로 표시하면 안 되는 범위

- 아이폰 실기기 전체 시나리오, 네트워크 단절·재접속 UX.
- 모바일 소셜 로그인 콜백/안전한 코드 교환: 이메일 로그인과 별개다.
- 실제 푸시 발송: 계정·토큰 종류 및 빌드 설정 필요.
- AI 실제 모델 응답 품질 평가와 장시간 큐 부하 검증.
- 공개 배포의 HTTPS·보안 설정·운영 DB 연결 및 백업 복구 검증.
- 퀴즈·포인트 서버 기능: 현재 API 계약이 없어 실제 기능처럼 표시하지 않는다.

앱 변경 및 최종 검증은 앱 저장소 docs/PRE_APP_TEST.md와 함께 확인한다.

## 실제 AI 재검증과 수정 결과

1. 기존 설정의 실제 process 요청은 120초 후 OLLAMA_TIMEOUT으로 실패했다.
2. JSON 스키마 전체를 모델에 직접 전달하자 로컬 엔진에서 'failed to parse grammar'가 발생했다. 생성용 스키마는 타입·필수 필드·enum 등 구조만 남기고, 길이·개수·근거·숫자는 기존 Node/Spring 검증기로 검증하도록 분리했다. 검증을 없앤 것이 아니다.
3. 스트리밍 진단에서 65초 동안 약 194개 조각이 수신되고 용어 설명을 길게 작성하고 있음을 확인했다. 모델 자체가 중단됐다고 단정할 수 없어 프롬프트를 짧은 요약·최대 두 핵심 용어 설명·짧은 카드 다섯 장으로 구체화했다.
4. think=false·temperature=0 유지, 작업별 출력 토큰 상한, length 종료 거부, 안전한 토큰 수·모델 지연 관측을 추가했다. 카드 프롬프트 버전은 card-v2-compact다.
5. 모델 1회 제한은 180초, Spring은 카드 재생성 최대 2회를 고려해 370초로 조정했다. DB 작업 lease 10분보다 짧다. 개인 컴퓨터 부하에 따라 더 느려질 수 있으며 큐가 생성 속도를 높여 주는 것은 아니다.

**실제 성공 결과(10/3):** RUN_AI_SMOKE=true LiveAiIntegrationTest 통과. Spring→Node→Ollama→PostgreSQL에서 요약·용어·768차원 임베딩 저장과 카드 생성/검증/DB 저장을 확인했다. process 46.6초(모델 45.7초, 임베딩 0.84초), 카드 103.5초. 테스트 데이터는 rollback한다.

합성 시험 기사 한 건의 성공이며 일반 뉴스 20건의 사실성 평가·성능 보장은 아니다. 실패 시 기존 콘텐츠 유지 및 오류 표시 원칙은 그대로다.

근거: [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs)는 format 필드의 JSON Schema 사용과 별도 응답 검증을 설명한다. 이 환경의 문법 호환 문제와 지연은 직접 실행해 확인했다.

## 앱 추가 연결과 보고서에 기록할 결과

- React Native 앱: 뉴스·검색·원문·카드·이메일 가입/로그인·SecureStore·401 단일 갱신·저장/해제·용어 학습·통계 연결.
- 마이페이지에서 소비 CRUD·월 집계·예산·실제 집계 기반 AI 설명, 정책 목록/상세/즐겨찾기, 알림 읽음 화면에 진입한다.
- 앱 TypeScript 검사, 통신 단위 테스트 6개, iOS Hermes 번들 생성 통과. 실제 iPhone 검증은 아직 아니다.
- 추가 서버 시나리오 테스트: 가입→검색→저장 두 번→저장 목록 1건→읽음→학습 통계→토큰 갱신→로그아웃→재접근 거부 통과.
- SDK 범위 내 의존성 보안 패치를 적용했지만 앱 npm audit 경고 17개(중간 12, 높음 5)가 남는다. 강제 SDK 다운그레이드는 하지 않았다. 공개 배포 전에 검토해야 한다.
- 주식·개인화 추천·정책 추천 프로필 편집은 서버 API가 있어도 앱 UI는 미연결이다. 소셜/푸시와 달리 이 부분은 외부 계정만의 문제가 아니라 추가 앱 개발 범위다.

최종 회귀: Spring 전체 74개 중 73개 통과·실모델 1개 조건부 제외. 제외된 실모델 테스트는 별도 RUN_AI_SMOKE=true 실행에서 통과했다. Node AI 테스트 13개, 앱 HTTP 테스트 6개 통과. 실기기 테스트와 GitHub Actions 실행 결과는 포함하지 않는다.

검증용으로 띄운 Node AI 서버와 임시 Metro 프로세스는 종료했다. 앱 테스트 전 실행 가이드대로 서버를 다시 시작해야 한다.

이번 작업의 완료 범위는 **핵심 흐름 및 소비/정책/알림 API 연결과 자동 검증**이다. 제안서 전체 기능·최종 제출물을 모두 완료했다고 보고서에 작성하면 안 된다.
