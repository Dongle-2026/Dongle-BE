### 3-2. Docker 켜기

Docker Desktop 앱을 열고 준비될 때까지 기다린다. Mac의 '터미널' 앱을 열어 아래 명령을 실행한다. 코드 블록의 명령만 복사한다.

```sh
docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

이 문서 작성 시 youthletter-postgres는 정지 상태, youthletter-redis-test는 실행 상태였다. 현재 상태는 위 결과가 기준이다.

다음은 **이미 있는 컨테이너를 시작하는 명령**이다. 삭제·재생성이 아니다.

```sh
docker start youthletter-postgres youthletter-redis-test
```

성공 확인:

```sh
docker exec youthletter-postgres pg_isready -U youthletter
docker exec youthletter-redis-test redis-cli ping
docker port youthletter-postgres 5432
```

기대 결과: PostgreSQL은 accepting connections, Redis는 PONG, 포트는 15432가 포함된다.

### 3-3. 복제 DB가 실제로 있는지 확인

```sh
docker exec youthletter-postgres psql -U youthletter -d postgres -tAc "SELECT datname FROM pg_database WHERE datname='youthletter_iphone_20260929';"
```

`youthletter_iphone_20260929`가 출력되어야 한다. 아무것도 안 나오거나 접속 오류가 나면 **다음 단계로 넘어가지 말고 결과를 보낸다.** 원본 DB로 이름을 바꿔서 실행하지 않는다.

복제 DB의 기사 존재 확인:

```sh
docker exec youthletter-postgres psql -U youthletter -d youthletter_iphone_20260929 -c "SELECT count(*) AS article_count FROM news_articles;"
```

0이면 화면에 뉴스가 안 보일 수 있다. 데이터 준비를 요청한다. 과거 확인값은 기사 84건이었지만 현재도 정확히 같아야 하는 것은 아니다.

### 절대 하지 말 것

- `docker compose down -v`, Docker 볼륨 삭제, DB DROP/초기화.
- 기존 DB에 `init.sql` 재실행.
- 오류를 피하려고 `ddl-auto=create` 또는 `create-drop`으로 변경.
- 예전 Compose 파일로 기존 DB 컨테이너를 무작정 재생성. 실제 15432 포트와 일부 파일의 5432 설정이 다르다.

SQL 파일이 있다는 이유만으로 자동 마이그레이션되는 프로젝트가 아니다. 테이블이 없다는 오류는 개발 담당자가 대상 DB·백업·적용 이력을 확인해야 한다.

## 4. Mac과 iPhone 연결하기 — 처음에는 AI 없이

### 4-1. 네트워크 준비

- [ ] 가능하면 MacBook과 iPhone을 같은 개인 Wi-Fi에 연결한다.
- [ ] iPhone 개인용 핫스팟에 MacBook을 연결해도 먼저 아래 Safari 검사로 실제 통신 여부를 확인한다. 같은 핫스팟이라고 접속 성공을 보장하지 않는다.
- [ ] Mac 시스템 설정 → 네트워크 → 현재 연결 → 세부사항 → TCP/IP에서 현재 IP 주소를 확인한다.
- [ ] VPN/방화벽 때문에 막히는지 확인한다. 보안 기능을 전부 끄지 말고 필요한 앱의 로컬 네트워크 접근만 허용한다.
- [ ] iPhone 설정에서 Expo Go의 로컬 네트워크 권한이 꺼져 있다면 켠다. 설정 메뉴 위치는 iOS 버전에 따라 다를 수 있다.

현재 Mac IP: __________  
예: 192.168.0.25는 **형식 예시일 뿐**, 그대로 사용하면 안 된다. 네트워크를 바꿀 때마다 확인한다.

### 4-2. 터미널 A: Spring 백엔드 실행

이 명령은 자동 크롤링·AI 작업자·정책 스케줄을 끄고 복제 DB에 연결한다. DB 구조는 validate로 확인만 하며 자동 변경하지 않는다. 신뢰할 수 있는 개인 네트워크의 개발 테스트 전용이다.

```sh
cd /Users/da-eun/Desktop/youthletter-backend
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:15432/youthletter_iphone_20260929 \
SPRING_JPA_HIBERNATE_DDL_AUTO=validate \
SPRING_DATA_REDIS_PORT=6380 \
AI_JOBS_ENABLED=false \
CRAWLER_CRON=- \
POLICY_NOTIFICATION_CRON=- \
./gradlew bootRun --args='--server.port=8080 --server.address=0.0.0.0'
```

처음에는 시간이 걸릴 수 있다. 터미널에 Started …Application이 나오고 종료되지 않으면 다음 검사로 간다. **이 터미널은 켜둔다.**

비밀번호 인증 오류는 현재 환경의 DB 설정을 확인해야 한다. 비밀번호를 문서에 붙이거나 원본 DB 설정을 바꾸지 말고 오류 문구만 보낸다.

### 4-3. 서버 연결을 세 단계로 확인

1. Mac 브라우저에서 `http://localhost:8080/api/health`를 연다.
2. iPhone Safari에서 `http://현재맥북IP:8080/api/health`를 연다.
3. iPhone Safari에서 `http://현재맥북IP:8080/api/news?page=0&size=1`을 연다.

성공 기준: health가 정상 JSON을 반환하고 DB·Redis가 정상이다. news는 JSON 안의 data.content에 기사 목록이 보인다. 예쁜 웹 화면이 아니라 글자로 된 JSON이 나오는 것이 정상이다.

**iPhone Safari의 2번이 실패하면 아직 Expo 문제를 볼 단계가 아니다.** 네트워크·IP·백엔드 실행 상태부터 해결한다.

### 4-4. 앱의 API 주소 입력

앱 폴더에 `.env.local` 파일을 텍스트 편집기로 열거나 만든다. 기존 내용이 있으면 지우지 말고 아래 항목만 추가/수정한다. 숨김 파일이 안 보이면 Finder에서 Command+Shift+.을 누른다.

```dotenv
EXPO_PUBLIC_API_URL=http://현재맥북IP:8080
```

실제 IP로 바꾼다. `/api`를 뒤에 붙이지 않는다. 예를 들어 현재 IP가 192.168.0.25일 때만 `http://192.168.0.25:8080`을 사용한다. `.env.local.txt`가 아니라 정확히 `.env.local`이어야 한다.

이 값은 앱에 노출되는 공개 주소다. DB 비밀번호·JWT_SECRET·AI_SERVICE_TOKEN을 EXPO_PUBLIC_ 변수에 넣으면 안 된다.

### 4-5. 터미널 B: Expo 실행

새 터미널 창/탭을 연다. A의 백엔드는 끄지 않는다.

```sh
cd /Users/da-eun/Desktop/Dongle-APP
npm ci
npx expo start --go --lan --port 8081
```

`npm ci`는 처음 준비하거나 의존성이 바뀐 뒤 실행하면 된다. 매번 할 필요는 없다. QR이 나오면 iPhone 기본 카메라로 스캔해 Expo Go에서 연다.

Expo 계정 로그인 안내가 나오면 Mac에서 `npx expo login` 후 iPhone Expo Go에도 **같은 계정**으로 로그인한다. 로그인/2단계 인증은 본인이 수행한다. 현재 공식 안내에서 iOS 실기기 Expo Go의 동일 계정 로그인을 요구한다. [Expo 실행 안내](https://docs.expo.dev/get-started/start-developing/)

터미널 B에서 Control+C로 Expo만 종료한 후:

| 14 | 알림 보관함·읽음·모두 읽음 | 알림이 있는 경우 읽음 상태 유지 |
| 15 | iPhone 네트워크를 잠시 끊고 재시도 | 오류를 보여주고, 복구 후 조회 가능 |
| 16 | 로그아웃 | 보호 기능은 로그인 요구 |
| 17 | 별도 버릴 계정으로만 회원 탈퇴 | 재접근 차단. 계속 쓸 계정으로 시험하지 않기 |

시험 금액 예: 등록 10,000원 → 수정 12,000원 → 삭제. 다른 소비가 없다면 해당 월 합계도 10,000 → 12,000 → 0으로 바뀌어야 한다. 실제 돈이 이동하는 기능은 아니다.

주의:

- 기사마다 생성된 카드·용어가 있는 것은 아니다. 없는 경우 원문/요약만 보여줄 수 있다. 카드/용어가 있는 시험 기사를 개발 담당자에게 요청하면 된다.
- 정책/알림이 비어 있는 것 자체가 오류는 아니다. 이 가이드에서는 자동 알림 스케줄을 끄므로 새 알림이 자동 생성되지 않는다. 임의 DB 수정 대신 시험 데이터 준비를 요청한다.
- 정책 정보는 오래된 자료일 수 있다. 실제 신청 가능 여부는 기관 원문에서 확인한다.
- 소비 등록 중 통신이 끊겼다면 먼저 목록을 조회한다. 성공 여부를 모르는 채 반복 등록하면 중복될 수 있다.
- 토큰 만료 시험은 로그인 후 약 16분 뒤 보호 기능을 사용하는 방식으로 진행할 수 있다. 실패하면 개발 담당자가 로그와 토큰 회전을 확인한다. 토큰 값을 직접 수정하지 않는다.
- 푸시가 오지 않는 것은 이 알림 보관함 테스트의 실패가 아니다. 실제 푸시 기능은 아직 별도 개발이 필요하다.

로그 전체 대신 필요한 오류 주변을 보낸다. 비밀번호·Authorization 헤더·accessToken·refreshToken·실제 소비 정보는 가린다.

## 7. 실제 AI까지 시험할 때만 추가로 할 일

### 7-1. 모델 확인

Mac에서 Ollama 앱을 켠다. 설치된 모델을 확인한다.

```sh
ollama list
curl http://127.0.0.1:11434/api/tags
```

qwen3:8b와 nomic-embed-text가 있어야 한다. 이 Mac에서는 앞선 검증에서 설치를 확인했으므로 먼저 목록만 확인한다. 없을 때만 설치/용량을 확인하고 개발 담당자에게 알린다. 처음부터 다시 다운로드할 필요는 없다.

이번 로컬 모델에는 OpenAI API 키나 유료 API 결제가 필요 없다. 다만 Mac의 메모리·전력·실행 시간이 필요하다.

### 7-2. 터미널 C: Node AI 서버

```sh
cd /Users/da-eun/Desktop/youthletter-backend/ai-service
npm ci
npm start
```

AI Service ready가 나오면 켜둔다. 별도 터미널/브라우저에서 확인:

```sh
curl http://127.0.0.1:3000/health
```

status가 UP이며 모델 존재가 확인되어야 한다. 기존 ai-service/.env가 있다면 오래된 모델명·120000 제한이 남아 있을 수 있다. 비밀값을 출력하지 말고 OLLAMA_TIMEOUT_MS를 현재 기본값 180000과 비교한다. 공유 토큰을 설정했다면 Node/Spring에 같은 값을 설정해야 하므로 연결 오류 시 개발 담당자에게 요청한다.

### 7-3. 내가 시험할 부분

- [ ] 앱에서 시험 소비를 입력한 뒤 '이번 달 소비 설명 요청'을 누른다.
- [ ] 실제 모델명과 rule-based-v1 기본 안내를 구분한다. 기본 안내는 모델 생성 성공의 증거가 아니다.
- [ ] 결과 숫자가 입력한 소비와 맞는지 확인한다. 금액 합계는 모델이 아니라 서버가 계산한다.
- [ ] 기사 요약/카드의 사실과 숫자·대상을 원문과 비교한다.

10/3 합성 기사 1건에서 요약/임베딩 약 47초, 카드 약 103초에 성공했다. 모든 기사에서 같은 시간이 걸린다는 보장은 없다. 현재 앱은 **미리 생성해서 DB에 저장된 카드 조회**가 기본이다. 화면을 열 때마다 새로 생성하는 구조가 아니다.

일반 앱 계정에는 기사 생성 권한이 없다. 시험 기사 생성, 관리자 계정 준비, 작업자 켜기·작업 큐 검증은 개발 담당자에게 요청한다. 네가 SQL로 본인 계정을 관리자 승격할 필요는 없다.

### C. 무료 서버와 독립 앱 배포

네가 먼저 답할 것:

- [ ] 발표 때만 Mac을 켜는 로컬 시연으로 가능한가?
- [ ] 다른 사람이 외부에서 접속해야 하는가? 언제까지, 몇 명 정도인가?
- [ ] 서버가 쉬는 시간 후 느리게 켜져도 괜찮은가?
- [ ] 0원 조건은 결제카드 등록도 불가인가, 과금 없는 카드 등록은 가능한가?
- [ ] DB는 시험 데이터만 올릴 것인가? 기존 데이터 일부를 옮길 것인가?
- [ ] 실시간 AI가 필수인가, 미리 생성한 실제 AI 결과 조회로 가능한가?

무료 서비스의 메모리·중단·저장 용량·백업·카드 등록 조건은 달라질 수 있다. 제공자를 아직 확정하지 않았으므로 **가입/배포 명령이나 무료 보장을 임의로 적지 않았다.** 위 답변을 받은 뒤 최신 요금과 한도를 검증해 배포 절차를 확정해야 한다.

Spring API/DB를 외부에 올리는 것과 qwen3:8b 모델을 외부에서 실행하는 것은 별개다. Mac에 Ollama를 둔 채 Mac을 끄면 외부 서버가 그 모델을 사용할 수 없다. 공개 서비스의 AI 운영 방식을 먼저 정해야 한다.

Expo Go 시연과 독립 설치 앱도 다르다. 독립 앱은 앱 식별자·네이티브 빌드·서명·배포 경로를 확인해야 한다. 개발 빌드와 스토어 배포는 동일한 완료 상태가 아니다. [Expo 개발 빌드 안내](https://docs.expo.dev/develop/development-builds/introduction/)

배포 전 개발 담당자가 확인할 일: 남은 의존성 보안 경고, 운영 비밀키, HTTPS, 접근 제어, 로그인 남용 방어, DB 스키마/백업 복구, 원본 데이터 노출 방지, 외부 AI 접근 통제. **로컬 개발용 기본 비밀값으로 공개 배포하면 안 된다.**
