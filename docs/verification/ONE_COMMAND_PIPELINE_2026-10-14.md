# 단일 명령 콘텐츠 파이프라인 검증 — 2026-10-14

## 검증 결과

- Docker 백엔드/AI 서비스 이미지 빌드 성공, DB·Redis·스키마 health 정상.
- Java 테스트 8개 통과: 원문+3종 작업의 저장, 재실행 중복 방지, AI 실패 시 원문 보존, 제한 재시도, 수집 실패 기록, 기사별 오류 격리, 크롤러 신규 기사 수 제한 및 기존 실패 처리.
- Python 테스트 4개 통과: 수집 시작 전 빈 대기열 오판 방지, 실패의 성공 오판 방지, 비밀값 권한/재사용, 일시적인 상태 조회 실패 후 작업 유지·완료·정리.
- 실제 한경 신규 기사 1건 수집, qwen3:8b 및 nomic-embed-text로 실행.
- 전용 DB에 원문 1건, 유효 요약 1건, 카드뉴스 1세트(5장), 퀴즈 3문항 저장.
- ARTICLE/CARD/QUIZ 작업 모두 SUCCEEDED. 최종 대기 0, 실패 0.

## 실제 실행에서 반영한 보완

처음 설정한 모델 호출 120초 제한으로 카드 작업이 시간 초과되어 기본값을 기존 AI 서비스와 같은 240초로 조정했다. 대기열의 자동 재시도로 카드 생성·저장이 완료됐다. 퀴즈는 생성 후 자체 검증에서 한 차례 재생성해 통과했다. 실제 AI 처리 시간은 요약/임베딩 약 85초, 퀴즈 생성·검증·재생성 약 335초, 성공한 카드 생성 약 111초였다. 기사와 컴퓨터 상태에 따라 달라진다.

검증 도중 Docker 상태 조회 하위 프로세스가 SIGKILL로 종료됐다. 진행 조회의 일시 오류 때문에 생성 작업을 종료하지 않도록 재조회 처리와 회귀 테스트를 추가했다. 최초 실행부터 수정 없이 종료한 검증은 아니며, 보완 후 실제 DB의 최종 결과 및 작업 상태를 별도로 확인했다.

검증용 컨테이너는 종료하고 전용 영속 DB 볼륨과 `.env.pipeline.local`은 보존한다. 다시 `./run-pipeline`을 실행하면 저장된 기사는 건너뛰고 신규 수집을 시작한다. 기존 개발·검증 DB는 변경하지 않았다.
