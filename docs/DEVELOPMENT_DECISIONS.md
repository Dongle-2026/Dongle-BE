# 구현 결정과 졸업작품 설명 근거

## 1. 뉴스 검색: 화면은 있지만 API 조건이 없었던 문제

문제: 프론트는 키워드 검색·카테고리 필터를 제공하지만 서버 목록은 category만 받았다.
선택: 기존 `/api/news`에 keyword/date를 추가하여 페이지 형식과 DTO를 유지했다. 새 검색 서버를 도입할 만큼의 규모 근거가 없어 JPA 조회로 시작한다.
연결: Controller 파라미터 → Service 정규화 → Repository 검색 → 기존 DTO.
검증: PostgreSQL 통합 시험에서 category+keyword+date 동시 조건과 null 조건을 확인한다. timestamp null 바인딩 오류는 명시적 cast로 수정했다.
한계: LIKE 검색은 대규모 본문에 느릴 수 있다. 실제 실행계획/데이터 규모 측정 후 전문 검색 인덱스를 도입한다.

## 2. 소비 집계: AI보다 먼저 계산 결과를 바로잡기

문제: 9월 소비를 8월로 수정하면 9월 필터 안에 이전 CREATED 이벤트가 남아 두 달에 집계될 수 있었다. 추세 조회는 DELETED 이벤트도 포함했다.
선택: 사용자별 전체 이벤트에서 최신 상태를 먼저 선택한 다음 월과 삭제 조건을 적용한다. 같은 created_at에서는 id DESC로 결정한다. generate_series로 당월 포함 여섯 달을 생성하고 빈 달은 0으로 채운다.
연결: 소비 event → 최신 상태 → 기간 필터 → 집계 → BigDecimal DTO → AI.
직접 변경: 월 목록·카테고리 집계·추세 쿼리 수정. 자동 갱신 로직 없는 snapshot 우선 반환 제거.
검증: 실제 PostgreSQL에서 삭제 및 월 이동 이벤트를 넣고 당월 0, 이전 달 200을 확인하는 회귀 시험.

## 3. 카드뉴스: 실제 생성과 저장을 연결

문제: 기존 생성 API는 정적 카드만 만들고 먼저 기존 결과를 삭제했다.
선택: AI 호출과 검증을 DB 트랜잭션 밖에서 수행하고, 성공 결과만 별도 Writer의 짧은 트랜잭션으로 저장한다. 기사 행 잠금으로 동시 최초 생성을 직렬화한다. 카드뉴스 ID를 유지하여 앱의 기존 링크가 깨지지 않게 한다.
연결: 관리자 generate → AiServiceClient → Node → Ollama → 양쪽 검증 → CardNewsWriter.
메타데이터: modelVersion, promptVersion, 카드별 sourceSentenceIds.
검증: 카드 수, 순서, 길이, 숫자 근거 테스트 및 실제 DB 교체/근거 저장 시험.
한계: 아직 durable queue/작업 상태 조회가 없으므로 관리자 사전 생성 방식이다. 앱은 생성 대신 조회 API를 호출한다.

## 4. 뉴스 AI 저장: 일부 실패를 성공처럼 집계하던 문제

문제: 전체 크롤을 한 트랜잭션으로 처리하면서 용어/벡터 저장 예외를 내부에서 무시했다. 후속 기사 실패가 앞선 기사에 영향을 줄 수 있었다.
선택: 외부 추론은 트랜잭션 밖에서 수행하고 기사별 Writer에서 요약·용어·임베딩을 함께 저장한다. 실패한 기사는 롤백되고 카운트가 실패로 남는다. 재처리 시 이전 요약을 만료하고 버전을 증가한다.
현재 범위: 단일 프로세스 크롤 중복 실행 가드. 여러 서버 간 분산 락과 durable 작업 재시작은 후속 단계.

## 5. 소비 AI: 숫자는 코드, 문장 제안은 모델

문제: 기존 응답은 실제 데이터 없이 “식비 15% 증가, 3만원 절약”을 고정 반환했다.
선택: 서버가 실제 당월/전월 금액 문장을 만들고 AI는 숫자 없는 점검 제안만 생성한다. 오류 시 규칙 기반 안내를 반환하며 모델명으로 구분한다.
이유: 사용자별 집계와 권한은 Spring에, 언어 생성과 프롬프트는 Node에 둔다. 데이터 정확성과 언어 품질을 각각 시험할 수 있다.

## 6. 추천: 현재 데이터에 맞는 최소 구현

제안서의 난이도·퀴즈·인기도 점수는 현재 데이터 수집이 부족하다. 이번 구현은 최근 30일 읽음 1회와 북마크 3회 가중 평균 벡터를 사용한다. 동일 기사의 반복 읽음은 DISTINCT로 제한한다.

후보는 pgvector cosine 유사도 0.60 + 관심 카테고리 0.25 + 최신성 0.15로 정렬한다. 읽은 기사는 제외하고 최대 3개, 같은 카테고리는 최대 2개를 반환한다. 조건을 만족할 후보가 부족하면 3개 미만이 정상이다. 벡터가 없는 신규 사용자는 관심분야·최신성으로 동작한다.

현재 버전은 시간감쇠 벡터·퀴즈 난이도·클릭률을 구현했다고 주장하지 않는다. reasonCode는 계산 경로를 그대로 나타낸다. 금융 용어/정책의 기존 1536차원 벡터와 기사 768차원 벡터를 섞지 않는다.

## 7. 푸시: 기기 등록 API부터

등록/갱신/삭제 API는 사용자 ID를 JWT에서 가져오며 요청 본문에서 다른 사용자 ID를 받지 않는다. 같은 사용자 기기 등록은 upsert로 처리한다. 실제 FCM 발송에는 Firebase 프로젝트, 서비스 계정, 앱의 실제 token이 필요하다. 이번 단계는 DB 알림과 기기 등록까지이며 외부 발송 성공으로 표기하지 않는다.

## 8. 환경에서 발견한 추가 문제

- Git이 Xcode 사용권 동의 오류로 실행되지 않았다. 코드 편집은 가능하나 사용자 변경과의 Git diff 확인 및 커밋은 미수행이다.
- 초기 전체 시험은 테스트 DB 미실행으로 실패했다. 개발 DB와 분리한 테스트 컨테이너를 실행했다.
- init.sql에 card_news가 빠져 컨텍스트 검증이 실패했다. 데이터 보존형 upgrade-capstone.sql과 Compose 초기화 마운트를 추가했다.
- 설치 Ollama는 상세 JSON Schema 입력에 grammar 오류를 반환했다. JSON 모드와 애플리케이션 검증으로 조정했다.
- 모델이 원문에 없는 금융 용어 후보를 만들었다. 원문에 실제 등장하는 항목만 하이라이트로 채택한다.

이 항목들은 보고서의 “문제→선택 근거→직접 구현→검증 결과”에 사용할 수 있다. 실제 시험 수치는 VERIFICATION_RESULTS.md를 인용한다.
